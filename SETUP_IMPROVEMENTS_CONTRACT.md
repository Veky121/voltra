## Node endpoints

Existing enrollment remains; install command now automatically invokes interactive setup. Display 2 compact copy rows (Run installer, Paste connection string), no separate start command. Keep Local/External and Advanced collapsed.

- GET /api/admin/nodes/{node}/connection expands to {mode,connected,stage:"disconnected"|"starting"|"checking"|"ready"|"error",ready:boolean,detail:string,checked_at?:timestamp,revoked:boolean}. Connected means connector exists; ready ONLY after authenticated /api/system returns valid JSON. Root caches health per connection ~5 seconds; retries on explicit POST /api/admin/nodes/{node}/check. No direct fallback. Node request list adds stage,ready,detail for approved/completed rows.
- POST /api/admin/nodes/{node}/reconnect creates one-node recovery enrollment. Returns same shape as create enrollment plus recovery_node_id/name. Session is tied to that node on server, request and admin approval still required. Approval rotates connector and Wings secrets and UPDATES existing node without changing uuid/id/server assignments/allocations/settings. Request carries recovery_node_id from session, not hostname. Admin sees 'Reconnect NODE_NAME'. Same pending request approval/reject endpoints.
- Node POST /api/remote/enroll unchanged, response adds recovery:boolean. Poll approved adds recovery:boolean. New setup mode `voltra-node setup --reconnect` prompts connection string even if saved config exists, accepts ONLY recovery enrollment (check POST response recovery), saves recovery files and replaces prior private Wings config only after approval. Refuse mismatched node UUID to prevent recovery of wrong node. Preserve data directories and Docker/network settings in existing Wings YAML; replace auth/remote/private api only. Lost ACK recovery remains idempotent.
- POST /api/remote/connector/status with connector Bearer body {stage:"starting"|"checking"|"error",detail?:string}. Only fixed safe details accepted server-side; do not persist arbitrary terminal/logs/secrets. Node can report startup attempt/failure after approved persistence. Ready is Panel-probed only, never trusted from node. No need for node to report while normal Run online unless useful.

## Panel setup/login API (plain JSON)

- GET /api/setup/status public returns {needs_setup:boolean,setup_allowed:boolean,auth_enabled:boolean,public_url:string,access_mode:"local"|"public",tls_mode:"proxy"|"automatic",restart_required:boolean,dev_mode:boolean}. Fresh DB => needs_setup, setup_allowed only direct loopback. Existing dev install keeps local development identity until wizard is completed. Fresh/production routes remain unauthorized until setup finishes. UI directs remote bootstrap to run wizard locally; no unauthenticated remote admin creation.
- POST /api/setup/validate {public_url,access_mode,tls_mode,acme_email?}. Bootstrap only loopback or existing authenticated admin. Returns {valid:boolean,checks:[{name,status:"ok"|"error"|"pending",detail}],restart_required:boolean}. Requires actual Panel reachability/TLS probe for local or existing reverse proxy. Automatic HTTPS mode validates hostname/email and saves certificate provisioning intent; cert issuance requires routable domain/443; UI must honestly show pending/restart instead of claiming certificate installed. Root implements managed HTTPS listener using autocert plus reverse-proxy option. Automatic mode can be finalized only after HTTPS cert/probe succeeds, or staged configuration saved with admin account created and setup awaiting HTTPS verification before external access. Root will clarify exact pending response if changed.
- POST /api/setup/complete {username,email,password,public_url,access_mode,tls_mode,acme_email?}. Atomic one-time bootstrap, 12+ char password, creates/claims ONLY passwordless development admin if matching username; cannot overwrite existing password account. Returns {completed:boolean,restart_required:boolean,next_url:string}. Sets HttpOnly SameSiteStrict session cookie. After completed, DevMode must not bypass session auth. Setup writes server-managed settings, not env text from browser. No secrets in browser storage/URLs.
- GET /api/auth/session returns {authenticated:boolean,user?:{id,username,email,root_admin},csrf_token?:string}; unauthenticated returns 200 false.
- POST /api/auth/login {username,password} returns {authenticated:true}; POST /api/auth/logout. Browser sessions cookies, rate-limited login, Origin/CSRF checks. Frontend can use same-origin `api` fetch. Root may choose double-submit/Origin protection and then csrf_token omitted.
- Setup Gate should export default SetupGate({children}) and show full-screen compact setup/login UI when needed. On /setup explicitly render wizard even existing development DB. Unconfigured production automatically shows wizard; existing dev installation can show subtle setup entry without forcibly interrupting current local work. On successful complete, redirect to /admin/nodes to add first node. If session required and unauthenticated, show login. No password persistence in frontend. One or two fields per step, no dense paragraphs; match existing theme.
