# Node pairing implementation contract

Root owns Panel API, schema, core transport integration and tests. Website agent owns web/src/admin/node-pairing.tsx and node-pairing.css plus minimal infrastructure.tsx integration. Node agent owns cmd/node, internal/nodeagent, internal/nodetunnel and tools/node. Shared checkout contains pre-existing edits: preserve them. Do not commit. Keep original pterodactyl-vite untouched.

## HTTP API (plain JSON, not attributes wrappers)

- Admin POST /api/admin/node-enrollments body {max_nodes: number (0 unlimited), expires_minutes: number (default30,max1440), location_id?:number}. Returns {id,expires_at,max_nodes,approved_count,closed,connection_strings:{local:string,external:string},install_command:string,start_command:string,release_url:string}. Secrets returned only on creation. String format PANEL_URL#PAIRING_TOKEN. Local defaults PublicURL; external DaemonURL if publicly usable, otherwise PublicURL; do not invent network reachability. Both addresses editable/copyable in UI if needed.
- Admin GET /api/admin/node-enrollments returns {sessions:[{id,expires_at,max_nodes,approved_count,closed}],requests:[{id,session_id,hostname,platform,architecture,memory_mib,disk_mib,verification_code,remote_ip,status,node_id,connected,created_at}]}. No secrets. Poll ~2s while wizard open. POST /api/admin/node-enrollments/{session}/close. POST /api/admin/node-requests/{request}/approve body {name?:string}; POST .../reject. POST /api/admin/nodes/{node}/disconnect revokes connector credential and disconnects it. Admin GET /api/admin/nodes/{node}/connection returns {mode:"outbound"|"direct",connected:boolean}.
- Node POST /api/remote/enroll body {token,hostname,platform,architecture,memory_mib,disk_mib}. Returns {id,request_token,verification_code,expires_at}. Pairing token allows enrollment only. Request token unique per request, used as Bearer for GET /api/remote/enroll/{id}; returns {status:"pending"|"approved"|"rejected"|"expired",node_id?,connector_token?,configuration?:object,panel_url?:string}. Approved response safely retryable during request lifetime. Credentials/configuration only after admin approves. Connector saves response to private file then POST /api/remote/enroll/{id}/complete using request token, which destroys bootstrap access to credentials. Timeouts/rejections terminal.
- Configuration from approval uses stock Wings config but api.host=127.0.0.1, port=8080, SSL disabled, data /var/lib/voltra/volumes, remote=Panel URL. Wings callbacks go directly outbound to Panel web port. No incoming Wings management port. Default SFTP remains separately reachable only if configured by operator. Game ports separate.

## Outbound tunnel (same Panel web listener)

Shared package internal/nodetunnel (node agent owns) provides NewConn(*websocket.Conn) net.Conn wrapper, preserving byte streams over binary WS messages. Data messages max64KiB chunks; Close and deadlines work. Control payload is {"type":"open","id":"randomStreamId"}. Keepalive via websocket ping/pong and read deadlines.

- Connector opens authenticated WebSocket GET /api/remote/connector with Authorization: Bearer CONNECTOR_TOKEN. Panel authenticates hashed per-node credential in separate node_connectors table, creates active control session; new connection replaces older session.
- When Panel needs a TCP stream to this node's Wings, sends control open. Connector dials local Wings TCP 127.0.0.1:8080 then opens GET /api/remote/connector/streams/{id} using same Bearer token; Panel accepts only pending stream for this authenticated node/session. Bridge raw bytes via nodetunnel.NewConn and io.Copy, allowing HTTP streaming, WebSockets and signed upload/download without buffering whole bodies. No destinations supplied by Panel; local target fixed in private connector config.
- Connector reconnects with bounded backoff, stops cleanly on context cancel. Node agent exports Run(ctx, Config) error in internal/nodeagent for root integration tests. Config fields PanelURL, Token, WingsAddress string, optional HTTPClient *http.Client if needed; align actual implementation and document.

## Distribution

No git remote is configured. Do not invent a GitHub release URL. Provide self-hosted Panel install command via /install/node.sh and Linux binaries at /downloads/voltra-node-linux-amd64 and arm64. Root will serve tools/node/install.sh and artifacts/node binary files; build script tools/node/build.ps1 or equivalent. Installer downloads using Panel URL argument, requires HTTPS except explicit loopback development, installs Docker/Wings as needed with platform validation, installs voltra-node binary. Interactive `sudo voltra-node setup` prompts for connection string, prints matching code, waits for approval, writes private Wings and connector configuration, creates/enables systemd services. `voltra-node run` runs saved connector; setup can start service after pairing. Avoid command-line secrets. Installer must not leave fake success if prerequisites/downloads fail. Runtime must not overwrite pre-existing Wings config silently.
