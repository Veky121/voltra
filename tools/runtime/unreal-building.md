# Brickadia, Longvinter and Frozen Flame source checkpoint

No proprietary server process, token authentication, native RCON, query/peer transport, saving or gameplay has been exercised for these three profiles. Fixtures prove source orchestration and filesystem behavior only.

Explicit deltas from the imported recipes:

- Root approved replacing Longvinter's retired Git/LFS acquisition with official Steam server1639880. Original `SRCDS_APPID=1007` still means the separate SDK install. It is not silently reinterpreted as the server application. The new server app is fixed metadata and installs into the original `longvinter-linux-server` subdirectory. Existing config/save paths and all10 original configuration fields remain. No fabricated working legacy-Git option is offered because the current publisher repo contains no binaries.
- Longvinter no longer runs an unpinned packagecloud shell, Git restore/stash, destructive directory removal or chmod777. AUTO_UPDATE now governs the managed startup update and reinstall preserves operator worlds whether it is on or off. This deliberately corrects the original description promising loss of savegames when updates are disabled.
- Query/RCON fields retain original names but fixed defaults become blank allocation selection. Longvinter's query field and Frozen Flame's RCON field become editable. Each native service needs a distinct selected allocation and valid1..65535 port, correcting imported65536 bounds. Allocator metadata chooses values deterministically through shared setup APIs.
- Frozen Flame's malformed shell shebang/curl overwrite and `^^C` stop are corrected. Missing config gets a pinned publisher default; existing custom balance settings and unknown fields survive. Blank SRCDS_APPID still suppresses automatic startup update, while explicit installation knows app1348640. Native RCON password remains its original argv switch; no client/bridge or new public listener is invented.
- Brickadia uses a pinned Linux runtime rather than a floating Mono image for the native Linux binary. Original `exit` console command remains, and optional world/name/password/public-listing controls remain. World path traversal is explicitly rejected; names with spaces remain valid.
- INI writes use exact native sections while preserving comments and unknown keys. Duplicate managed keys fail rather than silently selecting one. Private settings use mode0600. The installer retains file bytes, mode and numeric owner/group across actual replacement or publisher failure, and copies save content to disk rather than buffering it in RAM.

All original28 variables remain.
