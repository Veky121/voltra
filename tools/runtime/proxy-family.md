# Imported Minecraft proxy family

`stage-proxy-family-profiles.mjs` stages the six exact imported recipes under `.local/proxy-games/profiles.json`. The two WaterdogPE paths remain distinct catalog imports using the same publisher asset. Regeneration preserves reviewed status/detail for an unchanged revision. Root owns catalog merge and promotion.

All recipes use the existing managed Java backend and shared React setup. Original version/build/JAR/custom-URL controls remain, including Travertine's `DL_LINK` and VIAaaS's `WEBSERVER_PORT`. Dotted Minecraft versions are accepted. Invalid builds fail explicitly; custom URLs require a SHA256 and placeholders are substituted as data rather than shell evaluation. VIAaaS manages `bind-addresses[0]`: replacing its whole YAML array through Wings would turn it into a string, as the retained first native failure demonstrates.

Default publisher assets are pinned in `proxy-family-releases.json`: Velocity4.3.0/44 requires Java25; Waterfall1.21/615 and archived Travertine1.16/191 run under managed Java21; VIAaaSv0.5.2 and the official WaterdogPE latest asset require at least Java17 and default to21. Waterfall is end-of-life and Travertine is archived. The current official WaterdogPE asset reports version2.0.4 with `Development Build:true`; it is not represented as a stable release. Original Jenkins build selection remains available with an operator-reviewed checksum when that historical distribution is reachable.

The installer verifies executable jar metadata, preserves ownership/modes, caches verified public jars per volume, and seeds native configuration only when absent. Backend lists, forwarding secrets, plugins, resource packs, native identity/TLS files and configuration stay operator-owned. Velocity's forwarding secret is generated once with cryptographic randomness. No Minecraft EULA is accepted on behalf of a proxy operator.

VIAaaS requires distinct allocated game TCP and HTTPS ports. WaterdogPE reserves primary UDP RakNet/TCP built-in signaling and a separate UDP WebRTC allocation; its default `both` transport preserves modern NetherNet and legacy RakNet. Private STUN discovery defaults off; real advertised addresses, TLS or NXS settings remain operator configuration. No external account or credentials are fabricated.

Checks: `node tools/runtime/test-proxy-family.mjs` and `go test ./internal/panel -run '^TestProxyFamilyStagedDefaults$' -count=1`. Native query tooling sends only Java status/nonce or RakNet discovery and an HTTP NetherNet advertisement GET; it never sends player login or SDP offers. Acceptance reports are `artifacts/<family>-proxy-live-acceptance.json`, including `waterdog-duplicate` for the second original recipe. These distinguish listener/configuration/reinstall/clean-stop proof from untested player forwarding, Microsoft/Mojang/Xbox authentication, WebRTC sessions and gameplay.

Native `greload` was verified for Waterfall/Travertine and `velocity reload` for Velocity. Waterdog listener changes were accepted after a native restart. Strict reinstall retained bytes, mode, UID and GID; cleanup removed only each owned test server, installer/container/volume, allocations, egg and nest before its queue lease was released. All Windows subprocess helpers use `windowsHide:true`.
