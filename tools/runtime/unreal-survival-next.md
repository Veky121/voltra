# Aloft, Astro Colony and ASKA source checkpoint

All three profiles are source-only. No private Steam account, GSLT, publisher game process, server session, peer traffic or gameplay was exercised.

Primary references reviewed on 2026-10-23:

- https://aloft.wiki.gg/wiki/Dedicated_Server_how-to documents the game-bundled dedicated mode, separate create/load stages, current `create#name#`, `islandcount`, `corruptioncount`, `creative`, names, visibility, island protection, slots, port and repeated administrator tokens. https://aloft.wiki.gg/wiki/Multiplayer says an owning Steam account/client is required and the dedicated mode is not a separate anonymous Steam tool. App1660080 remains unchanged. Owning-account transport is not available in our secure Steam helper, so installation with credentials remains explicitly failclosed. No fake anonymous success or external client files are used.
- Astro Colony's developer directly links their maintained documentation at https://steamcommunity.com/app/1614550/discussions/0/6369856944152116857/ to https://docs.google.com/document/d/11sC1F2HdSymO44Hklg3nfrO5D66YIs7rEUrGV1GjpDM/edit. The document itself was not accessible through web tools. Original pinned Linux app2934900, binary and all11 INI fields therefore remain the source baseline, without claiming current publisher verification for every field. Password, map seed/name, players, admins, load-latest, technology/oxygen/construction and autosave interval/count are all emitted into the original section.
- ASKA publisher announcement https://store.steampowered.com/news/posts/?enddate=1732559519&feed=steam_community_announcements describes the separate Steam server tool and editable server properties file. Publisher's Dedicated Server Information post https://steamcommunity.com/app/1898300/discussions/0/4635988286620392822/ links https://docs.google.com/document/d/13N9pDSmmSG9iM5JwS2pjLiyY566XZZd1ED79itIvg4k/edit. The detailed Google document was not fetched. Original app3246670, executable, propertiesPath, all6 properties, SteamAppId1898300 and operator-provided GSLT are preserved. No token is created or supplied by fixtures. Server token authentication itself remains unverified.

Explicit source deltas:

- Astro Colony's query field changes27015 to blank automatic selection over selected allocations, becomes editable, and requires a distinct query allocation. `-Port=<primary allocation>` is now explicit, fixing the imported launch command that silently used the Unreal default. `-SteamServerName` is one literal argv token without the imported shell backslash/quote artifacts.
- Aloft's original combined `create#name#500#0#` remains the default legacy mode. Current publisher syntax is a separate explicit selection with island/corruption presets. `NUM_ISLANDS` continues to control legacy syntax and is never silently converted to a preset. Existing world folders skip creation. A failed creation status or missing expected world folder prevents loading. Compatibility of the legacy500-island request with today's game remains unverified.
- All Aloft administrator IDs are emitted as distinct literal repeated tokens. `#`, traversal and shell command injection in names/IDs are rejected. Original alphanumeric map and alpha-dash server name restrictions remain. Original Wine debug/DLL overrides/private prefix/save path and editable Winetricks verbs remain. Winetricks receives a literal argument array, is taken from the checksum-pinned image, uses its own upstream download validation, and stamps completed prerequisites only after success. Microsoft runtime/media prerequisites still require native acceptance.
- Aloft's background Wine plus incorrect tail PID is replaced by one supervised process with Unity `-logFile -`. File log retention is preserved by installation but startup no longer overwrites server.log/create.log. This avoids an orphan tail keeping the container alive after game exit. Actual publisher stdout readiness remains unverified.
- ASKA keeps the native `server properties.txt` name, updates only imported keys and preserves unknown settings including existing save ID. Token/password stay in mode0600 properties and are redacted from native console output. Startup with blank GSLT is explicitly blocked. No new port control or relay claim is invented where the original recipe provides none.
- Windows titles keep stock Wine on the pinned image with a volume-local `.wine`; no Proton substitution or host-wide Wine changes. Native console Stop uses shared PTY ETX. This routes Ctrl-C, but does not prove proprietary game saving or Wine shutdown behavior.

The Linux filesystem fixtures mock only Steam/subprocess publishers. They assert all11 Astro INI controls, all6 ASKA properties, complete old/current Aloft command grammars, existing-world behavior, private flags, tokens absent argv, malformed input rejection, private Winetricks invocation/caching/failure handling, original app/platform selection and actual failed-publisher byte/mode/UID/GID retention. Source archives include exact emitted helpers and a SHA256 manifest, plus staged eggs. Root owns canonical integration.
