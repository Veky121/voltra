# Farming Simulator 25

Game Library includes a reviewed adaptation of [nn-home-com/farming-simulator-25-egg](https://github.com/nn-home-com/farming-simulator-25-egg/tree/3ad302f2a67726567a534c964cc423c76d2d1d88), MIT licensed. Source is vendored under `internal/panel/game_library/fs25`; changes there are embedded into the preparation script. Installed eggs retain their content identity across later updates.

Choose Farming Simulator 25, a Linux x64 node, storage and a web-manager password. Ports are assigned automatically. Preparation creates folders and installs reviewed helpers. Start from Console to perform the licensed GIANTS download, Wine installation and activation. This can take a long time. Defaults are 6 GiB RAM and 100 GiB storage, including temporary installer space.

Use a separate GIANTS server licence. The setup links to Admin integrations with the imported egg and `GAME_SERIAL` mapping preselected. Blank licence uses that egg's saved licence; a supplied licence overrides it. Both paths store the serial encrypted. Existing integrations scoped to a different egg must be explicitly remapped; licences are not copied between games or versions. A serial is not a GIANTS API key. Never put a real serial in tests, reports or screenshots.

For manual installation, disable automatic downloads and upload the official Windows installer into `/installer`. Previously activated licence files may be supplied through the normal file manager. Do not use a Steam player purchase as the server licence.

## DLCs

Automatic DLC download is opt-in. It fetches Windows DLC installers offered by GIANTS for the configured serial. Independently purchased packs may need their own product key. Upload their official installer to `/dlc`, set the advanced DLC product key, and restart. Install separately keyed packs one at a time. Clear that override before returning to automatic DLC installation with the base serial. Increase the bounded DLC timeout for larger packs.

Successful installer exit plus new nonempty `.dlc` files records an installation marker keyed by the installer hash. This prevents repeated activation when GIANTS uses a different payload name. Failed new payloads move to `/dlc/failed` so the game cannot load an incomplete file. Savegames, mods and installed DLCs live under `/data`. Game settings includes shortcuts to those folders.

Installer completion does not establish that a DLC loads or that clients can join. Check game logs for loaded/available DLC and test a player with matching content. The upstream README's claim that red/corrupt markers are harmless was verified only for its small CR11 unlock pack, not every DLC. Large packs and first-time GUI activation remain unverified in Voltra. Upstream reports should not replace game-specific checks.

## Source audit, 2026-10-25

No obvious credential exfiltration, miner, unexpected callback or licence bypass was found in the reviewed repository source. This is a source review, not proof that every binary in the third-party container matches its source. Vibe coding does not establish trust.

The runtime image is pinned to GHCR digest `sha256:10073fd00ab197e36c45dd8af94ca297c04ae2a4288d4b3bd65c16aa468b8dc8`. The third-party dependency image still requires trust. Voltra supplies the lifecycle and helpers locally rather than downloading scripts at server start. The image's entrypoint evaluates STARTUP, so this recipe uses a fixed startup string with no operator-controlled shell interpolation.

Changes from upstream:

- Render XML with escaping, private file permissions and no `sed` replacement expansion.
- Limit downloads to the licence-gated GIANTS portal and HTTPS GIANTS CDN hosts, including redirects. Bound response size, download size and request duration. Rename downloaded installers only after completion; incomplete files are never executable installer candidates.
- Honour any uploaded installer. The original multi-argument `ls` presence check required all patterns to match.
- Supply activation keys to `xdotool` on stdin, clear the field with Backspace and type slowly. Original typing exposed the key in process arguments and could drop characters.
- Remove the stable-file-size shortcut for DLC success. A stalled download also has a stable size. Require installer exit and nonempty new payloads; quarantine failed payloads.
- Bound base installation and portal HTTP requests, remove the default `changeme` password, and encrypt serial/password overrides with existing integration storage.

No licensed game, paid DLC, public connection or gameplay is claimed tested by this change. Automated checks cover recipe import, port allocation, encrypted credential snapshots, XML rendering and download failure handling using fixtures.


## Voltra save-before-stop bridge

`VOLTRA_FS25_SAVE=true` enables the server-side Lua bridge and local worker on the next prepared start. It defaults to false for existing compatibility. Console's Save game action requires `control.console`. Normal client Stop and Restart save first, require a fresh native success message for that request, stop the game session through the web manager, confirm it is offline, and only then send container power to Wings. A failed, stale, concurrent, timed-out, or unconfirmed request sends no power action. Force Kill explicitly bypasses saving.

The bridge needs no connected player or player-hosted service. It polls BaseMission.update because ordinary mod update callbacks do not run while an empty dedicated server pauses. DediAutoSave conflicts with explicit saving: that mod blocks FSBaseMission.saveSavegame while empty. Disable DediAutoSave before enabling this bridge; Voltra reports the conflict instead of claiming success. The usual script-mod matching rules still apply to clients. Console crossplay and joining with the additional mod are not claimed verified.

Live validation on October 30 used the existing world, zero connected players, a backup, and a temporary private join password. Native saves succeeded while empty and paused. Save-and-stop confirmed both native saving and game-session shutdown. A full container restart loaded slot 1 with matching saved metadata and all 45 save files unchanged. The complete startup wrapper also started its worker automatically, and its subsequent save-and-stop succeeded. No game download or duplicate online licence was used.

The initial failed polling attempt timed out without reporting success or stopping the game. Protocol tests cover stale confirmations, concurrency, errors, missing workers, stop confirmation, permissions, and explicit Force Kill. Direct web-manager Stop/Restart is outside Voltra's power preflight. External Wings/Docker shutdown deadlines can force a container off; allow more than the native 60-second save timeout plus portal shutdown time for that path. Scheduled power tasks have a separate short timeout and are not covered by the client-power preflight.


### Shutdown confirmation hotfix

Nightly 25 accepts a completed save-and-stop proof only from the current worker session and only for 15 seconds. This prevents the shutdown wrapper from requesting another save after Wings has started terminating Wine. The CLI helpers also accept that proof for wrappers already running during an update. Live validation on October 31 confirmed the Voltra Stop endpoint saved the world and the container exited with code 0, followed by a successful Voltra Start request. This runtime-only correction does not require a desktop UI change.
